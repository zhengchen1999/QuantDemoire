## 2. 补齐最终部署权重的验收

- 为选中的 .25% W4/W8 权重生成实际 shape 记录，评估已有调度及新权重上的调度候选。
- 使用独立进程、相同真实 UHDM 输入、交替顺序比较调度；按整网结果选取。
- 验证最终配置下融合、特征释放及变化输入 CUDA Graph 的完整图输出一致性。
- 在 500 对测试图上运行最终部署 CUDA 和匹配的 fakequant，保存逐图哈希与指标。
- 核对校准状态、导出整数码、mask、FP16 尾部、量化参数和 smoothing 一致。
- 最终 profile 发生变化时重新测量严格分支成本；30% 未通过时保留明确失败状态。
- 同权重/profile 测 eager、Graph、模型常驻及峰值 allocated/reserved；FP16 基线使用
  适用的相同通用融合和特征释放，同时提供 FP32 显存对照。

## 3. 整理公开入口和目录

- quantdemoire/：ESDNet、校准、fakequant、部署加载、指标与运行时。
- kernel/：W4/W8 整数卷积、FP16 稀疏分支、融合、构建与严格成本诊断。
- script/：数据准备、从头 PTQ、fakequant/CUDA 质量、E2E、显存、导出和验证入口。
- config/：可移植相对路径、论文/调整/部署配方、最终调度及对照配置。
- tests/：发布路径的数值、格式、融合、Graph、数据和来源验证。
- docs/：安装、复现、格式、结果和已知限制；把历史研究记录与当前说明区分。
- results/：仅纳入最终逐图结果、必要对照、配置和哈希证据；清理对本机路径的依赖。
- uv.lock、pyproject.toml、.python-version：固定环境；检查 wheel 包含所有 CUDA 源文件。
