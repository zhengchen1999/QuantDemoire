# ESDNet / UHDM 后续执行计划

制定于 2026-09-30，依据 [进度核验](AUDIT_20260930.md)。范围限定为 ESDNet/UHDM、
W4A4、W8A8 和浮点参考。Hugging Face 暂只准备本地格式和加载接口。

## 目标与验收口径

1. 两种位宽使用真实 INT4/INT8 CUDA 计算；离群值用 FP16 保存和参与运算，
   允许 FP32 累加。每个量化层保留 smoothed weights 排序后两侧各至少 0.25%
   的原始极值，包含并列值时通过稳定排序保证数量。
2. FP16 分支开销的严格口径沿用 kernel 文档：
   `R_core = (完整量化路径时间 - 匹配的无稀疏主路径时间) / 整数主计算时间`。
   增量包括稀疏专用输入准备、索引访问、运算、合并及新增中间存储。
   另报以完整主路径为分母的 `R_pipeline`。两种位宽分别验收，目标均为 ≤30%。
   汇总采用同一批次各层时间之和；同时完整披露逐层结果，不能把汇总通过称作逐层通过。
3. 端到端比较使用同一硬件、输入、输出、浮点累加精度和执行模式；FP16 基线
   采用适用的相同通用优化。报告 eager 和 CUDA Graph，并纳入输入量化、
   smoothing、packing、稀疏分支及全部网络输出。
4. 校准、fakequant、导出、CUDA 必须有可核对的同一套稀疏结构和量化参数。
   改变 mask 或量化语义后重新校准/评估，旧分数不自动继承。
5. 论文质量复现与额外权重训练的部署结果分别标记。当前 QAT 权重保留作为已验证
   参考，不能作为严格 PTQ 复现的替代品。

## 阶段 1：固定基线，修复复现链路中的依赖

- 为当前源码、模型包、配置和基准结果建立内容哈希清单及可恢复的本地版本记录。
- 建立独立实验目录，所有试验使用新的结果文件名，避免覆盖历史测量。
- 用空的独立 JIT 缓存从当前 CUDA 源码重新编译，检查是否依赖旧目标文件或原型目录。
- 清理构建入口的本机路径依赖；记录 CUDA、CUTLASS commit、编译器、uv 和 PyTorch 版本。
- 固定两份性能参考：包内默认 profile，以及已测量的 feature release profile。
- 搜索本地所有 UHDM 数据和原始 checkpoint，核对官方划分；必要时补齐官方测试数据。
  下载前检查文件清单、大小、空间及重复内容。

产物：环境/源码/模型/数据清单、干净编译记录、基线配置和结果索引。
通过条件：源码可独立编译，原有正确性测试通过，基线数值与性能可重复。

## 阶段 2：建立最终调度下的分支成本测量

- 把现有 main-only 诊断整理为可复现的脚本，修正其依赖旧缓存目标文件的问题。
- 使用完整模型产生的真实中间特征，覆盖全部 157 个量化层及原生 4K 形状。
- 对照保持相同整数 tile、输出布局、激活、残差及适用的后继量化行为。
  仅关闭稀疏运算及稀疏专用准备；该模式只用于计时，不作为质量有效模型发布。
- 对融合算子按实际执行路径计时，每个准备/前缀算子只计一次，避免重复分摊或遗漏。
- 同时保存逐层 CUDA events、计算核心计时、完整主路径计时及全网络消融。
- 按额外毫秒数定位优先优化的层；结合可用 profiler 检查访存、同步、寄存器和
  工作负载分布。编译期资源数据不代替实际性能归因。

产物：可运行的分支开销入口、逐层明细、汇总表和热点排序。
通过条件：同一批次、同一源码和权重下可重复计算 R_core/R_pipeline；不借用公共
浮点算子的耗时扩大分母，不混合不同历史版本的计时。

## 阶段 3：优先解决 W4 FP16 分支，再验证 W8

先保留现有 mask 和算术顺序，检查是否能通过更少的稀疏输入搬运、局部复用、
更合适的行分组/负载分配，以及主计算与稀疏阶段的调度减少开销。
优化按实际热点排序；同时记录主分支是否被新调度拖慢。

若原结构仍限制性能，再筛选结构化或混合存储候选：

- 在小输出通道组内使用有界填充的分组布局，保留不适合分组的 CSR 项。
- 每个候选统计真实非零项、填充项、索引字节和激活读取量，再决定是否编写 CUDA。
- 两侧必须保留的极值通过显式必选集合约束；允许增加普通 FP16 项，但同时计算
  对权重大小、计算量和校准误差的影响。
- 局部通道重排必须恢复原通道语义；残差、concat 和消费者缓存保持一致。
- 若改变浮点累加顺序，使用独立数值参考和图像质量指标，不能沿用旧逐位等价结论。

此前的 8 输出通道 union Tensor Core 原型及多个联合版本均慢于 CSR；除非新的
分组方案能实测降低填充/准备成本，否则不重复扩展同类原型。

候选筛选顺序：小规模正确性 → 热点层性能 → 全形状 → 实际全网络。
没有稳定收益的候选保留简短失败记录，不进入默认运行路径。

产物：选中的 kernel/格式、必要的格式版本迁移、更新后的成本报告。
通过条件：尾部覆盖保持；数值检查通过；W4/W8 分别满足最终成本口径，且完整网络
没有性能回退。未达到时继续记录未达标，不能仅凭局部或更宽松分母宣布通过。

## 阶段 4：恢复论文 PTQ 配方，并在最终稀疏格式上校准

- 核对 activation/weight 的对称性、zero point、边界估计、padding 校正和舍入。
- 按 arXiv 核对 200 对训练校准图、512 裁剪、采样比例 0.001、smoothing alpha=0.5、
  4 epochs、Adam、初始学习率 0.001、循环余弦调度，以及频率提取层数和损失实现。
- 检查频率滤波核、dilation、VGG 特征层及损失权重；论文未明确的信息注明假设。
- 严格 PTQ 配置只训练论文允许的量化参数，不训练普通网络权重和 bias。
- 原论文每侧 0.5% 作为配方对照；部署结构允许每侧至少 0.25%。若最终结构不同，
  单独报告该部署变体，并确保它的 fakequant 和 CUDA 使用相同 mask。
- 将最终 mask 在校准前确定；校准后导出只做布局转换，避免导出时暗中重新选尾部。
- 用训练留出集选择范围/候选；正式测试集仅用于最终评估。
- 统一命令串联原始 checkpoint → 校准 → 导出 → 格式检查 → fakequant/CUDA 评估。
  全流程不依赖昨天保存的 quant_state；保留中间状态与恢复点。

数据准备和配置修复可先进行，最终校准等待稀疏结构确定。GPU 校准、计时和质量
评估顺序执行，避免互相干扰。

产物：论文配置、部署配置、校准状态、W4/W8 可部署权重及完整来源记录。
通过条件：稀疏结构与量化参数一致，原始 checkpoint 可重新生成完整评估产物，
额外 QAT 结果有独立标签。

## 阶段 5：全数据质量和端到端性能验收

- 在完整官方 UHDM 测试划分上重新测量 FP32、FP16、W4 fakequant、W4 CUDA、
  W8 fakequant、W8 CUDA 的 PSNR、SSIM、LPIPS，保存逐图结果和输入/模型哈希。
- 先核对 FP32 参考与论文的差异，再判断量化造成的损失；出现差异时检查数据、
  checkpoint、预处理、指标和参数，而不是用测试集调参。
- 精确算术保持的优化检查全图输出与 Graph 回放等价；数值语义变化的候选重跑质量。
- 将特征释放扩展到全测试图验证后纳入默认 profile。
- 重新测量速度与峰值显存；保留当前约 1.64× / 1.37× 的加速作为回归参考，
  更高速度作为优化目标，不预先声明尚未测量的结果。
- 评估 W8 compact-first-cache 与特征释放组合后的收益；旧的约 127.5 MiB 节约
  来自不同内存配置，必须重新测量其收益是否仍存在。
- 最终计时使用独立进程、交替测试顺序和多轮采样；报告中位数及波动。
  原生 4K 为主要性能口径，其他实际输入尺寸用于检查正确性和适用边界。
- 显存分别报告模型常驻、峰值 allocated 和 reserved，包含所有推理缓存。

产物：正式质量主表、逐图记录、kernel 开销表、速度/显存表与失败项。
通过条件：论文差异可解释；真实部署与对应 fakequant 一致；速度和显存来自同一个
最终权重/profile 组合；分支成本单独通过验收。

## 阶段 6：整理开源入口、模型格式和干净安装

复用已有脚本，统一参数、输出 schema、resume 和来源校验；仅为缺少的能力新增入口。

| 用户入口 | 预期职责 |
|---|---|
| `script/reproduce.py` | 数据校验、从头校准、导出、评估各阶段及完整流程 |
| `script/evaluate_fakequant.py` | 与最终部署格式匹配的质量评估 |
| `script/evaluate_cuda.py` | 真实整数部署质量评估 |
| `script/benchmark_e2e.py` | FP16/fakequant/CUDA 整网时延，明确 eager/Graph |
| `script/benchmark_memory.py` | 独立进程显存对照 |
| `script/benchmark_kernel.py` 和分支成本入口 | 全层数值、计时和 30% 开销验收 |
| `script/export.py` / `verify_release.py` / `package_model.py` | 格式导出、验证和本地 HF 包 |
| `script/setup_kernel.sh` | 有版本记录的源码编译 |

整理 `kernel/` 的 W4、W8、稀疏分支和融合实现说明，标明支持的硬件及分派逻辑。
发布包保存最终整数权重、FP16 尾部、量化参数、runtime、执行计划、模型卡和文件哈希。
模型目录移动后仍可加载；不依赖本机绝对路径和已有 JIT 缓存。

最后在独立干净目录用 `uv sync --frozen` 从头安装、编译和运行公开入口，检查
下载/恢复数据与权重所需的说明、许可证和第三方来源。整理源码、配置和必要证据的
Git 提交；大数据、缓存、原型二进制和重复实验输出不混入发布源码。
HF 地址保持未发布状态，待真正上传时填写。
