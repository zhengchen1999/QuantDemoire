# ESDNet / UHDM 历史部署实验记录

**历史记录**：本页保留早期 100 图和旧显存口径。最新完整测试集、公平的特征释放
对照及严格分支开销见 [当前执行记录](EXECUTION_20260930.md)。

这些是本地实测结果，不是论文完整测试集的重新发表结果。实验硬件为 RTX 4090，
环境由 `uv.lock` 固定。当前还没有达到全部加速验收条件，尤其是 FP16 分支开销
不超过主分支 30% 的要求。没有执行 Git push 或 Hugging Face 上传。

按最新要求固定已有 FP16 基线、仅为 W4/W8 启用新增特征释放的
[单张真实 UHDM 图像测试](UHDM_SINGLE_IMAGE.md)：W4/W8 分别为
**79.31 / 94.50 ms**，同批 FP16 为 **129.88 ms**；加速比
**1.638× / 1.374×**，峰值 allocated 显存节约 **55.32% / 46.96%**。
该次设置单独保存在 `config/experiments/uhdm_single_image.json`。

后续融合、已缓存特征省略和W4共享操作数查表使端到端耗时约为
**79.58 / 94.59 ms**；同批FP16为129.88ms，
约 **1.632× / 1.373×**，峰值显存节约约
**23.36% / 17.24%**。见
[共享查表、原版二进制对照与全100图验证](SHARED_W4_LOOKUP.md)。
最新推荐配置保存在 `config/experiments/optimized.json`；进一步的
[联合 kernel 调优](JOINT_PIPELINE.md) 和 [跨层调度实验](JOINT_DISPATCH.md)
分别保留实测记录。下面的性能表是较早测量批次，质量指标继续由完整等价验证关联。

上一版 CSR 元数据内核的[主分支独立对照](MAIN_ONLY_DIAGNOSTIC.md)保留下一层量化及残差融合，关闭稀疏
计算和辅助输入准备。排除共同浮点算子后，量化层 GPU 累计开销增量为 W4 34.60%、
W8 24.06%；这是含输入准备的匹配调度诊断，不是逐层或计算核心 30% 验收通过。

## 质量

所有下列结果使用相同的 100 对 UHDM 本地测试图，原生 2160×3840 分辨率。
网络输入补齐到 2176×3840，输出裁回原尺寸。图像和模型哈希见
[数据清单](../results/dataset_manifest.json) 和 [质量汇总](../results/quality_optimized_summary.json)。
训练/校准使用 200 对图像，选取范围及训练候选使用另外 24 对训练图，未使用测试集选取。

| 模式 | PSNR ↑ | SSIM ↑ | LPIPS ↓ | 相对 FP32 的 PSNR 下降 |
|---|---:|---:|---:|---:|
| FP32 参考 | 22.45877 | 0.790169 | 0.275242 | — |
| FP16 操作数 / FP32 累加 | 22.45879 | 0.790156 | 0.275205 | 约 0 |
| W4A4 fakequant FP16 | 21.36227 | 0.757579 | 0.321811 | 1.09651 |
| W4A4 CUDA + FP16 分支 | 21.36113 | 0.757551 | 0.321718 | 1.09765 |
| W8A8 fakequant FP16 | 22.27718 | 0.788828 | 0.273952 | 0.18160 |
| W8A8 CUDA + FP16 分支 | 22.27702 | 0.788833 | 0.273932 | 0.18176 |

上表 CUDA 采用 `main_output=float16`。论文表 4 的 PSNR 下降为 W4A4 1.04 dB、
W8A8 0.12 dB，见 [arXiv 原文](https://arxiv.org/html/2510.04066v1#S4.T4)。
当前差距接近这一量级，但本地子集和完整官方测试集不能直接比较绝对分数。

W4A4 在现有校准状态上另做了 4 个 epoch 的量化感知微调，固定原始离群值
位置和 FP16 数值，更新普通整数权重、bias 和激活步长。因此不能将它描述为
严格按原论文配方进行的 PTQ 复现。W8A8 使用普通权重 minmax 范围及训练留出集
选取的 1.75 倍激活范围，没有这一步额外权重训练。

fakequant 与 CUDA 使用同一份整数码和 CSR 离群值，默认 fakequant 的普通权重
反量化后还会舍入到 FP16，因此不承诺与整数 CUDA 逐位一致。逐层正确性测试
另用 FP32 伪量化 oracle，并模拟稀疏分支 FP16 操作数的舍入。

## 早期原生 4K 性能与显存

[同一轮 eager 测量](../results/memory_compact.json) 包括全网络、三个输出、量化、
packing、smoothing 和 FP16 稀疏分支；不包含图片 I/O 或质量指标。
每种模式在独立进程中测试。FP16 基线采用 FP32 卷积累加，禁用 TF32。

| 模式 | 延迟中位数 ms | 相对 FP16 加速 | 模型常驻显存减少 | 峰值 allocated 变化 |
|---|---:|---:|---:|---:|
| FP16 | 137.754 | 1.000× | — | — |
| W4A4 + FP16 分支 | 117.082 | 1.177× | 58.8% | 减少 8.2% |
| W8A8 + FP16 分支 | 130.642 | 1.054× | 35.0% | 减少 3.0% |

模型常驻显存下降不等于峰值显存下降，两者在上表分别实测。新的输入通道映射
只保存稀疏权重用到的 planar 激活通道，累计少写约 6.13 GB/次推理的中间数据。
这不是峰值显存节约量。FP16/W4A4/W8A8 的峰值 allocated 分别约为
3.255 / 2.988 / 3.159 GB。W8A8 已测得小幅加速，收益仍然有限。

`main_output=float16` 将主分支零点校正、bias 融合进整数卷积
epilogue，在 FP32 校正后将中间结果存成 FP16；稀疏分支继续 FP16 操作数、FP32
累加。压缩 planar 通道之前，延迟为 W4A4 122.469 ms、W8A8 136.136 ms，见
[W4A4](../results/e2e_cached_half1_4.json)、[W8A8](../results/e2e_cached_half1_8.json)。
通道映射没有改变任何稀疏位置或权重值；两种位宽在全部 100 张测试图上的三个
整网输出均与压缩前逐位相同，见 [等价验证](../results/compact_network_equivalence.json)。
旧的 FP32 中间结果性能保留在 [历史记录](../results/memory_eager.json)。

**稀疏分支 30% 开销目标仍未达到。** 压缩前的 157 个量化层汇总中，W4A4/W8A8
分支增量分别约为整数卷积核心的 217.9% / 147.8%，或完整主路径的 95.6% / 76.0%。
通道压缩后的完整逐层计时已完成：上述比例分别降到 **196.2% / 128.4%**，或
完整主路径的 **85.8% / 66.1%**；见 [最新逐层汇总](../results/kernel_compact_summary.json)。
整网加速不能代替这一独立的开销验收。分项 profiling 和计时消融见
[性能拆解](PERFORMANCE_BREAKDOWN.md)。

## 正确性与验收

- 两种位宽均使用真实整数 Tensor Core 主分支，INT32 累加；157 个量化卷积不回退到浮点卷积。
- 第一和最后一个卷积保留 FP16，所有 159 个卷积权重形状都进入测试覆盖。
- 原始 smoothed weight 的两侧排序尾部各至少 0.25% 已逐层核对，见
  [W4A4 格式检查](../results/final_format_4.json)、[W8A8 格式检查](../results/final_format_8.json)。
- 本节早期测量配套单元测试包含 19 项：packing、饱和/舍入、concat、padding/stride/dilation、
  尾部输出通道、非默认 CUDA stream、切换输入的 CUDA Graph，以及压缩通道映射。
- FP16 中间结果版本的两种位宽各 159 个原生 4K 层形状全部通过数值检查，见
  最新压缩版 [W4A4](../results/kernel_compact_4.json)、[W8A8](../results/kernel_compact_8.json)。
- 缓存校正和调整线程映射后的完整网络输出在首张原生 4K 图上与前版三个输出
  均逐位相同，见 [整网等价检查](../results/cached_network_equivalence.json)。
- 每层计时同时报告相对整数卷积核心及相对整个主路径的开销，保留全部失败项；
  不能更换分母后将未达标结果描述为已达标。

可复现命令见 [REPRODUCE.md](REPRODUCE.md)，格式见 [FORMAT.md](FORMAT.md)，
CUDA 源码与开销定义见 [kernel/README.md](../kernel/README.md)。
